# 会议访客账号与邮箱验证（2026-10-15）

## 使用流程

会议网站右上角提供注册、登录入口。未登录点击已启用的会议报名/投稿，会进入带会议名称的登录页，可切换创建参会账号。填写常用邮箱并完成图片验证码后，系统发送一小时有效的邮箱验证链接；验证后完善原生账户信息、设置密码，自动登录并继续原会议报名或投稿。

邮箱验证链接在另一个浏览器打开后也保留返回目标。原生登录支持邮箱或用户名。同一遇见科技账号可参加多个会议，创建账号不会自动产生报名或投稿记录，仍需完成会议的业务表单。

入口为 `/event/<会议ID>/login/`、`/event/<会议ID>/register/`，并进入原生 `/login/?next=...`、`/register/?next=...`。会议主页的入口返回该主页，报名/投稿入口返回对应业务页面。页面显示会议名称、返回会议链接、登录/创建账号切换；登录后隐藏访客注册入口。完整模板、旧模板与原生投稿页面均保留可用的手机入口。

延续现有邮箱验证链接机制，没有新增数字邮箱验证码或机构SSO。参考站的机构登录属于其自身服务，不是本轮实现范围。

## 修复与权限

- 修复共享 `portal.js` 刷新会话时把会议登录链接重置成通用登录入口。
- 修复原生注册验证邮件未携带返回目标的问题：仅在有效会议上下文中扩展当前请求的发送方法，继续使用原生邮件发送、签名和期限。
- 保留原生邮箱验证、CAPTCHA、CSRF、限流、密码规则、重复邮箱/用户名及已验证邮箱匹配检查，没有独立账号库或验证绕过。
- 别的站点、别的会议、路径穿越、反斜线/控制字符及越界ID不能作为新增入口的返回目标；越界ID在数据库查询前拒绝。
- 未发布、撤回、无权访问或已删除会议不向匿名注册页面泄漏会议名称。公开注册不会改变会议访问权限。
- 按实际原生验证码DOM修复320px图片加载后的按钮溢出；仅调整布局，播放、刷新及服务端验证仍由原生组件处理。
- 原生认证控制器仅在实际发送时导入，避免单独导入渲染器时触发未完成模型注册的问题。
