# 2026-10-23 审查问题修复与验证

## 改动

- 已有财务订单的报名，阻止在原生后台撤销、重置、改价、修改报名或额外开放修改期限。单笔、批量操作均取得报名行锁，与支付回调和重新支付串行执行。
- 微信和支付宝支付信息记录有效期。未过期时复用；过期后查单，已付款则登记到账，未付款则确认关单后换支付单号。公司订单号保持不变，回调匹配当前支付单号。
- 支付宝未打开的旧链接可能仍能创建交易，查无交易时复用同一个支付单号，避免产生两个可付款交易；新链接同时设置绝对截止时间。查询或关单结果不确定时保留原记录，等待重试。
- 验签通过但报名被旧代码修改后的到账记为“到账待核对”，保留金额、流水、审计记录，重复通知不重复入账。不自动批准失配报名、不允许开票；支持申请并由财务登记实际全额退款。
- 基本信息编辑器未改动起止时间时，保留原生秒和微秒；真正修改时间时仍按原规则校验日程边界。
- 页面隐藏过期二维码和支付链接，提示从原支付方式重新获取；增加异常到账状态、筛选、说明和退款入口。

## 验证范围

- `tests/backend/verify_review_regressions.py`：10 项回归，包含并发重新支付、原生单笔/批量变更拦截、查询失败保留旧单、已付款查单、支付宝旧链接恢复、关单期间支付竞态、真实 RSA 签名及篡改拒绝、时间精度、异常到账幂等和退款。
- `tests/backend/verify_payments.py`：原有报名收费、银行转账确认、重复流水保护、开票、全额退款、权限、导出、微信/支付宝签名回调及并发通知。
- `tests/browser/verify_payments_ui.cjs`：付款界面中英文、草稿、过期二维码隐藏和重新获取、异常到账退款入口，320/390/1440 像素布局。
- 前端生产构建、API 错误消息测试、15 个扩展 Python 文件语法检查。
- 服务检查：Docker 六个容器、自动恢复策略、本机和内网首页、登录页及会议 61。

新增回归先在原代码上复现失败，再在修复后验证。测试只使用可识别的临时账号和会议，结束后标记删除，不修改会议 22、61、171。邮件使用内存后端；支付 HTTP 由测试替身拦截，未发生真实付款或退款。
