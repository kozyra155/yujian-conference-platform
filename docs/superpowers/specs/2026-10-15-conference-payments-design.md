# 遇见科技统一收款

用户已确认前述报名、收款、确认、退款、发票申请和财务导出流程，并指定资金统一进入遇见科技公司账户。本轮直接实施，不再重复请求设计批准。

复用 Indico 报名金额、审核、PaymentTransaction 和通知；公司收款设置由平台管理员维护，会议管理者只能配置本会议收费、查看和导出本会议订单。人民币为本流程唯一币种。普通/学生票可用不同报名表或原生收费选项；早鸟票用单独报名表的开放截止时间。

报名审核通过后生成金额快照和唯一订单号。参会者只可访问本人订单；汇款信息提交后仍为待核对，只有平台管理员可以凭银行流水确认到账。未配置账户时禁止付款，不能提供虚构收款资料。金额由后台计算，重复请求和重复到账确认不能重复入账。报名金额变化后拒绝旧订单收款，需要人工处理，不静默改价。

微信 Native 和支付宝网页支付使用公司本机商户配置、RSA 签名、服务端验签、金额和商户校验及幂等回调；公网 HTTPS 回调及必要密钥缺失时关闭通道。浏览器返回页和用户“已付款”不能标记支付成功。密钥不通过业务 API 返回。

退款先申请，由公司财务在银行/支付商户后台实际退款后记录流水；当前仅支持全额退款，退款记录同时撤销报名。开票先收集个人/企业抬头、税号和邮箱，财务在实际开票后登记票号；付款确认单不称为税务发票。所有财务动作保留操作者、时间和原因。

界面沿用现有蓝绿品牌、Element Plus、工作台导航与中英切换；320px 可用。新增公司收款配置、会议收费/订单页、个人付款详情和打印确认单。测试使用临时会议、临时账号和内存邮件；不改会议22/61，不调用真实扣款或退款，不发送外部测试邮件。

存储使用每报名一行原生 EventSetting JSONB 保存订单及申请，PaymentTransaction 保存到账/撤销交易。通过报名行锁串行修改，银行流水通过数据库事务锁防重复。当前无需新增数据库迁移；大量财务记录时应迁移独立订单表并增加索引。
