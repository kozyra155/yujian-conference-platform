## 访问入口

- 平台：http://localhost:12880/
- 会议 A：http://localhost:12880/event/1/
- 会议 B：http://localhost:12880/event/2/
- 登录：http://localhost:12880/login/
- 会议 A 栏目管理：http://localhost:12880/event/1/manage/layout/menu/
- 会议 B 栏目管理：http://localhost:12880/event/2/manage/layout/menu/

使用 `localhost`；系统配置绑定该主机名，直接使用 `127.0.0.1` 可能返回 404。本机若有代理，需要为 localhost 设置直连。

## 与目标产品的关系

上游已有会议创建、会议级权限、自定义菜单、富文本内容页和外观设置。本地初始化脚本调用上游模型与操作，未修改上游源码。

本演示不等于已完成面向客户的一键建站。2026-10-13 已增加参考 CASCONF 首页的遇见科技门户，见 [首页改版记录](portal-frontend.md)。后续仍需将默认栏目和模板初始化接入主办方的创建流程，并调整会议详情的经典侧栏设计。

Indico 默认使用会议路径；独立子域名需要域名路由、DNS 与证书适配。页面编辑保存通常直接生效；设计文档中的草稿、预览、发布快照和回退未实现。

本轮未验证报名、投稿、审稿、支付、邮件送达或大规模并发，不将菜单或源码中的模块存在视为业务验收通过。

首版建议继续复用 Indico 的会议、权限和内容管理；在其上增加创建向导、经典侧栏模板及遇见科技门户。若需要保存草稿后集中发布，须另设发布版本，不能直接把原生保存按钮改名为“发布”。

## 运行边界与修正

本机 Docker / WSL 虚拟机在构建期间两次中断，原因未确定。最终使用已构建镜像补装渲染库并修正脚本换行、字体缓存权限，修正同时写入主 Dockerfile；当前镜像重建容器后仍通过上述检查。从零构建修正后的完整 Dockerfile 未再次跑完，生产环境稳定性未验证。

初始化脚本曾因同一请求内切换用户时的请求缓存分配错会议创建者，已按 Indico shell 的 REPL 模式执行，并明确指定创建者、修正演示账户权限；模型和真实登录检查均重新通过。此项是本地初始化脚本问题，不是已确认的 Indico 权限漏洞。

原生富文本编辑器约有 200ms 的内容同步延迟。自动化保存检查等待隐藏字段同步完成后再提交，已证实最终内容可被匿名读取；极快点击保存的边界尚未修正或单独验收。
